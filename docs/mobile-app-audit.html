01 High

Refresh tokens sit in plaintext SharedPreferences, and Android backs them up

Security

lib/core/sync/services/auth_service.dart:113 · android/app/src/main/AndroidManifest.xml

saveToken() writes the whole AuthToken — access and refresh token — as jsonEncoded text into SharedPreferences. flutter_secure_storage is not in pubspec.yaml, so nothing reaches Keychain or Keystore.

The manifest sets neither android:allowBackup nor dataExtractionRules, so it defaults to true. The backing XML — refresh token included — is swept into Android auto-backup and into adb backup. A refresh token is a long-lived credential: whoever holds it can mint access tokens until it is explicitly revoked server-side.

Fix Move the token pair to flutter_secure_storage, and set android:allowBackup="false" (or exclude the prefs file via dataExtractionRules). Migrate existing users by reading the old key once, re-writing it securely, then deleting it.

02 High

The local database is unencrypted, and it holds the most sensitive content in the app

Security

lib/core/database/sync_database.dart · pubspec.yaml

There is no SQLCipher dependency and no PRAGMA key anywhere in the database layer. Every note, prayer, prayer log, person record and Bible bookmark is stored as plaintext SQLite.

This app's data is unusually personal — private prayers, named people, spiritual journaling. It inherits the same allowBackup problem as the token above, so the entire corpus leaves the device in backups. This is a product-risk call as much as a technical one.

Fix At minimum, close the backup escape hatch alongside finding 01. If the threat model includes a lost or shared device, encrypt at rest with sqlcipher_flutter_libs and a Keystore-held key — plan it as a migration, since it rewrites the database file.

03 Medium

The notes list re-sorts the full collection inside build()

Performance

lib/features/notes/presentation/screens/notes_home_screen.dart:609 → _sortNotes

The notes section filters the note list and calls _sortNotes() over all of it — every single rebuild, on the UI thread. _sortNotes() copies the list and sorts the copy, so the cost is the whole collection each time.

With a few hundred notes this is invisible. It scales with the user's whole corpus, and it is paid on each keystroke in the filter field, each folder tap, and each sort toggle — the interactions where dropped frames are most noticeable.

Fix Move the filter/sort into a derived provider so Riverpod caches it, and have the widget watch the already-sorted result. .select() is used well elsewhere in this codebase (see overview_grid.dart) — the same approach applies here.

04 Medium

Large accessibility font sizes have no ceiling anywhere in the app

Accessibility

app-wide — 0 occurrences of textScaler / textScaleFactor

There is no textScaler clamp in the widget tree, against 395 fixed-pixel height constraints in features/ and shared/, and exactly one FittedBox in the codebase.

At the 200% system font setting both platforms offer, text grows but those containers do not, so rows overflow. The codebase already knows it is height-sensitive — the comment in main.dart notes that six layouts are sized as a fraction of screen height. That sensitivity applies to type scale just as much as to rotation.

Fix Clamp globally in MaterialApp.builder with MediaQuery.withClampedTextScaling(maxScaleFactor: 1.6, ...), then walk the worst offenders — list rows, stat tiles, the bottom bar — and replace fixed heights with minHeight constraints.

05 Medium

Reactive queries are almost entirely unbounded

Performance

lib/core/sync/repositories/ · 44 watch() vs 7 limit()

The repository layer exposes 44 .watch() streams and applies .limit() in only 7 places. Providers such as notesStreamProvider therefore hydrate the user's entire table into memory, and re-emit the whole list whenever any single row changes.

Every write — including one arriving from sync — re-runs the query, re-materialises the list, and rebuilds each screen watching it. Cost is proportional to total corpus size rather than to what is on screen.

Fix Page the list-backing streams (a limit tied to the scroll position), and for counts use a COUNT(*) watch instead of watching rows and calling .length.

06 Medium

Seventeen files exceed 800 lines, concentrated in screens that mix four concerns

Maintainability

17 files > 800 LOC · 41 files > 500 LOC

notes_home_screen.dart (2,016 lines) holds the folder tree, the notes list, smart collections, filtering, sorting, multi-select and the trash view in one State class with 356 app-wide setState call sites feeding into it. group_detail_screen.dart (2,008) defines just 6 private methods across that span.

The consequence is the one already visible above: because everything shares one build(), unrelated state changes trigger the expensive tree and list work. Splitting the file is what makes findings 04 and 05 straightforward rather than delicate.

Fix Extract each section into its own ConsumerWidget so rebuilds scope naturally. Start with the two sections named in findings 04 and 05 — the refactor and the performance fix are the same edit.

07 Low

Thirty-seven UI files still carry hardcoded strings, and only English ships

i18n

37 files under features/ and shared/ with no l10n reference · lib/l10n/ contains only app_en.arb

Adoption is strong (1,271 call sites), which makes the holdouts conspicuous — including user-visible section headers such as headerTitle = 'ALL NOTES' in notes_home_screen.dart:768. Mixed-language UI is worse than uniformly untranslated UI, so these become visible the moment a second locale ships.

Fix Sweep the 37 files into the ARB before adding any locale. The l10n(context) helper already exists for exactly this.

08 Low

Custom tap targets bypass the accessibility affordances IconButton gets for free

Accessibility

57 GestureDetector · 52 InkWell · 51 Semantics references

IconButton usage is near-exemplary at 122 tooltips out of 125. But 109 custom tap targets sit outside that discipline, with only 51 Semantics references in the whole app to cover them. A bare GestureDetector announces nothing to TalkBack or VoiceOver and has no minimum touch size.

Fix Audit the GestureDetector sites that act as buttons: wrap in Semantics(button: true, label: …), or switch to InkWell inside a 48×48 target.

09 Low

Debug logging ships in release paths

Hygiene

71 print / debugPrint call sites outside generated code

debugPrint is not compiled out of release builds. Several sites log sync and auth state, which both leaks detail into device logs and costs string interpolation on paths that run often.

Fix Route them through the existing SyncLogger, or gate on kDebugMode. The infrastructure is already there — this is just the call sites that never adopted it.
